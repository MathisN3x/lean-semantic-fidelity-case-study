
# Semantic Fidelity in AI-Driven Autoformalization

A reproducible case study investigating whether an AI-generated Lean proof preserves the mathematical reasoning of its original natural-language proof.

## Overview

Autoformalization aims to translate mathematical content expressed in natural language into a formal language that can be checked by a proof assistant.

However, a proof accepted by a proof assistant is not necessarily a faithful representation of the original mathematical argument.

This repository presents an independent case study of this distinction. It compares an original mathematical proof, written in natural language, with a Lean 4 implementation generated by a large language model.

The experiment focuses on the following question:

> Does a successfully verified Lean proof necessarily preserve the mathematical reasoning of the original proof?

The case study is inspired by the semantic fidelity problem discussed in:

**Bastounis, A., Circelli, F., & Hansen, A. C. (2026).** *Navier–Stokes Lost in Translation: Why Lean Verification of AI Autoformalisation Does Not Guarantee Correct Natural Language Proofs.* [arXiv:2610.08144](https://arxiv.org/abs/2610.08144).

## The Mathematical Problem

The experiment uses Problem 1 from the 2026 International Mathematics Competition (IMC).

**Problem.** Show that the equation

$$
\cos(\cos x)=\sin(\sin x)
$$

has no real solution.

The original proof was independently written by the author before requesting its formalization.

The official problem statement is available in this repository:

- [`IMC_2026_p1.pdf`](IMC_2026_p1.pdf)
- [`IMC_2026_p1.tex`](IMC_2026_p1.tex)

## Experimental Setup

The experiment follows a simple procedure:

1. Write a mathematical proof of the problem in natural language.
2. Submit the proof to an AI model with a request to generate Lean code.
3. Compile the generated Lean implementation.
4. Compare the mathematical reasoning in the original proof with the reasoning used in the generated implementation.

### Model and Configuration

| Component | Configuration |
|---|---|
| AI model | Claude Sonnet 5.5 |
| Proof assistant | Lean 4 |
| Lean version | `4.37.0-rc1` |
| Original proof | Written by the author |
| Lean implementation | Generated by the AI model |
| Verification | Successful compilation |

### Prompt

The model was given the following instruction:

> "Write Lean code that compiles for the following proof, and just give me the code."

The prompt is included here to make the experimental procedure transparent.

## Results and Observations

The generated Lean implementation was successfully accepted by Lean.

However, comparing the two proofs reveals differences in their mathematical reasoning.

In particular, the generated implementation uses a different approach in parts of the argument rather than preserving the original proof strategy.

This observation illustrates an important distinction:

- **Formal correctness:** Lean verifies that the generated proof establishes the stated proposition under its assumptions.
- **Semantic fidelity:** The formal proof preserves the mathematical meaning and reasoning of the original argument.

Successful compilation provides evidence of formal validity, but does not, by itself, establish semantic fidelity.

Importantly, the use of a different proof strategy does not make the generated proof mathematically incorrect. Whether this constitutes a failure depends on the objective: proving the theorem or faithfully formalizing the supplied proof.

## Reproducing the Experiment

The Lean implementation requires Lean 4 and Mathlib.

The experiment was tested using Lean version:

```text
4.37.0-rc1
```

The implementation imports Mathlib:

```lean
import Mathlib
```

To reproduce the verification, use a Lean 4 environment with a compatible Mathlib installation and open `lean-implementation.lean` in the Lean editor or project environment.

The successful compilation reported here corresponds to the configuration specified above.

## Scope and Limitations

This repository documents a single experimental case study. It is not a systematic benchmark of autoformalization systems or a general evaluation of the model's mathematical capabilities.

The experiment illustrates a possible discrepancy between formal validity and the preservation of mathematical reasoning. Its findings should therefore be interpreted within the scope of this particular problem, prompt, model, and implementation.

A broader investigation would require multiple mathematical problems, models, prompts, and formalization attempts.
